# 零售门店商品真伪受理系统

门店收到顾客的商品真伪质疑时，登记**商品型号、销售单、包装批次、防伪码与封签照片**；
店员先核对本店销售记录与供应批次，无法确认的上交**总部质控复查**，复查期间**标记/冻结相关库存**。

零第三方依赖：Python 3.11 标准库（`http.server` + `sqlite3`），证据图片为本地生成的**虚构 SVG 凭证**，
防伪查询、供应商确认、短信/邮件通知均为**模拟适配器**。

## 一条命令启动

```bash
./run.sh                 # 或 python3 -m app.app
# 打开 http://127.0.0.1:8000
```

启动时自动建库、生成证据图片，并自带完整演示案例（含跨门店**重复码**案例）。
加 `--reset` 可清空后重新种子；`PORT=8080 ./run.sh` 换端口。

## 演示案例（启动即有）

| 防伪码 | 情形 | 结果 |
|---|---|---|
| `AC-DUP-7777` | **重复码**：09-28 南京中山路店首查判真 → 10-01 苏州观前街店同码再现 → 10-02 杭州店码查询 | 归并同一原调查、重新升级、追加冻结，等待总部 V2 改判 |
| `AC-FAKE-0001` | 防伪库无此码 + 销售单不存在 + **供应商否认批次** L202609X | 总部认定假冒，批次冻结待处置 |
| `AC-DMG-1234` | **标签刮损** + 顾客**仅带外包装** | 总部无法认定，库存维持冻结待补证 |
| `AC-OK-5555` | 包装/销售单/供应批次三方一致 | 门店核对无异常，未上报 |

页面右上角可切换操作身份（门店 / 总部 HQ）。用门店身份打开重复码案件，
可点"以门店身份尝试修改结论"验证 **403 权限拦截**；在"库存与冻结"页对冻结批次
点"模拟销售一单"验证 **409 出库拦截**。

## 功能与页面

- **受理登记**：型号/销售单/包装批次/防伪码/封签情况/顾客联系方式；提交即自动做三方证据比对，
  发现重复码、刮损、销售不匹配、供应商否认等线索自动上报总部并冻结本店相关库存（同一事务）。
- **防伪码查询**：模拟防伪平台；同一码再次出现**只关联原调查并留痕，不生成新案**。
- **调查列表**：可"仅看关联冻结批次"；展示首次出现时间/门店、当前结论版本。
- **证据对照页**：按证据来源排列——① 顾客包装/防伪码/封签 ② 本店销售记录 ③ 供应批次/供应商
  ④ 总部质控复查 ⑤ 系统比对与查询留痕；重复码顶部横幅显示**首次出现时间与门店**及后续每次出现。
- **总部复核**：仅 HQ 可出具结论（真品/假冒/无法认定），改判生成**新版本**，历史版本与全部证据保留；
  冻结/解冻与结论**同事务**更新。
- **客户告知**：模拟短信/邮件网关；门店只能依据总部已生效结论代为转达。
- **库存与冻结 / 审计日志**：冻结流水、出库验证、全部关键动作留痕。

界面为白底 + 深灰，警示黄只用于风险/冻结/异常；结论文本与复查说明使用完整换行容器，始终可读不截断。

## 关键业务规则

1. **调查归并**：同一防伪码（大小写/空格归一化，刮损码另有指纹）多次查询或多店受理，
   一律 `merged_into_id` 指向原调查；原案已闭环则自动重新升级。
2. **冻结与结论同事务**：`BEGIN IMMEDIATE` 取写锁，销售出库与冻结互斥；
   判真→同事务解冻，判假→连锁同批库存全部冻结，无法认定→维持冻结。
3. **结论版本**：`conclusion_versions` 保留 V1…Vn，改判记录 `supersedes_version` 与改判发现。
4. **门店权限**：门店不能出具/修改总部结论（403），不能操作他店案件，不能在总部出结论前告知判定。
5. **证据完整**：防伪码重复、标签刮损、销售记录不匹配、仅外包装、供应商否认、复查改判
   六类情形均产生独立证据/发现记录与凭证图片。

## 测试

```bash
python3 -m unittest discover -s tests -v
```

15 个用例覆盖：

- **调查归并**：重复受理归并、码查询不产生孤岛案件、已闭环案件重复码触发重开；
- **库存冻结**：冻结批次直接拒售；8 线程并发销售 + 冻结，断言冻结提交后**无一单售出**、账实一致；
- **结论版本**：V1→V2 改判、旧版原文保留、连锁扩冻、无法认定维持冻结、理由必填；
- **门店权限**：门店出结论被拒、越权改判被拒、他店告知被拒、结论前告知被拒；
- **证据留存**：刮损/仅外包装/供应商否认/销售不匹配/重复查询各自留有完整证据。

## 目录结构

```
app/
  db.py               SQLite schema、事务（BEGIN IMMEDIATE）、枚举
  adapters.py         模拟防伪平台 / 供应商门户 / 通知网关
  evidence_assets.py  本地虚构凭证 SVG 生成（包装、封签、销售单、供应商函、HQ 意见书）
  services.py         核心领域服务：受理/查询/归并/冻结/复核/告知/销售
  seed.py             演示案例（含重复码主线与时间线回写）
  web.py              JSON API + 静态文件（http.server）
  app.py              启动入口
  static/             前端（原生 HTML/CSS/JS）
tests/test_service.py 规则与并发测试
run.sh                一条命令启动
```

## 主要 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/investigations?frozen=1` | 调查列表（可按冻结批次筛选） |
| GET | `/api/investigations/{id}` | 详情（证据对照/版本/查询留痕/冻结流水/通知） |
| POST | `/api/intake` | 门店受理（自动比对、上报、冻结、归并） |
| POST | `/api/code-search` | 防伪码查询（重复码关联原案） |
| POST | `/api/hq-review` | 总部复核/改判（仅 `actor_store=HQ`） |
| POST | `/api/investigations/{id}/notify` | 门店按总部结论告知顾客 |
| POST | `/api/demo/sell` | 销售出库（冻结批次返回 409） |
| GET | `/api/inventory?status=FROZEN&store=S01` | 库存 |
| GET | `/api/audit` | 审计日志 |
