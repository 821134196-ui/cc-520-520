# 零售商品真伪质控台账（模拟系统）

门店受理顾客的商品真伪质疑 → 查防伪码 → 比对证据 → 复查期标记库存 →
总部质控复核出结论（可改判）→ 告知顾客的全流程台账。纯 Python 标准库实现，
**零第三方依赖**，SQLite 落库，证据照片/凭证存本地，防伪查询与短信走模拟适配器。

## 一条命令启动

```bash
python3 run.py            # 建库+灌入演示数据+起服务，打开 http://127.0.0.1:8000
```

启动即自带一个**重复防伪码案例**：同一码 `ACF-A1-88880001` 先在城东旗舰店
受理并被判正品，随后在南站分店再次出现（封签破损），系统把第二个案件
**归并到原调查**，总部据新证据改判"疑似假冒"并把两店同批库存全部冻结。

常用参数：`--reseed`（重置数据）、`--seed-only`（只灌数据）、`PORT=8080`。

## 页面

| 路径 | 内容 |
|---|---|
| `/` | 案件列表，`/?frozen=1` **只看冻结/暂挂批次**的案件 |
| `/case/<id>` | 证据对照页：按**证据来源**排列 顾客包装/小票、门店销售记录、供应商批次、防伪平台、总部报告；重复码横幅显示**首次出现时间与门店**；相关库存状态；总部结论**逐版本完整展示**，旧版标注"已被取代"、当前版高亮 |
| `/images/<f>` `/docs/<f>` | 本地证据照片（程序生成 PNG）、虚构文本凭证 |

视觉：白底 + 深灰文字；警示黄只用于封签/平台这类需注意项，红色只用于
破损/假冒/冻结等危险态；结论文字 `white-space:pre-wrap` 始终完整可见。

## 六项业务能力（均为 POST JSON API）

受理 `POST /api/cases`、码查询 `/api/cases/<id>/query`、
证据比对 `/compare`、复查期标记库存 `/quarantine`、
总部复核 `/conclusion`、客户告知 `/notify`；另有 `/api/sell` 销售出库。
身份由请求头 `x-actor-role: store|hq` 与 `x-actor-store: <门店id>` 指定。

```bash
# 门店试图自行下总部结论 → 403
curl -X POST localhost:8000/api/cases/3/conclusion \
  -H 'x-actor-role: store' -H 'x-actor-store: 1' \
  -d '{"verdict":"genuine","text":"门店自行判正品"}'
# 销售已冻结批次 → 409 FrozenBatchError
curl -X POST localhost:8000/api/sell -H 'x-actor-role: store' \
  -d '{"store_id":1,"batch_id":1,"qty":1}'
```

## 关键业务约束（对应测试）

- **重复码归并**：第二次查到同码不另立孤立新案，新案 `original_case_id`
  指向原调查根案件；第三、N 次仍归并到同一根。首次出现时间/门店取自首查。
- **库存冻结与结论同事务**：总部 `issue_conclusion(..., batch_action=freeze)`
  在**同一个 `BEGIN IMMEDIATE` 事务**里追加结论版本、更新全部相关库存、
  写冻结事件；销售与冻结在 SQLite 写锁上串行化，竞态下疑似批次不可能售出
  （`tests` 中 5 轮 × 双销售线程 + 冻结线程，校验数量守恒与终态恒为冻结）。
  - 门店复查期只能 `quarantine`（暂挂本店库存）；总部才能 freeze/condemn，
    freeze/condemn **全连锁生效**，release 只解除挂在本案件下的库存。
- **结论版本化**：复查改判只追加新版本，`supersedes` 指向上一版，旧版全文
  保留，案件 `current_conclusion_id` 指向当前有效版。
- **门店权限**：门店不能出具/修改总部结论，拒绝操作落 `audit_log(allowed=0)`。
- **证据只增不删**：防伪码重复、标签刮损、销售记录不匹配、仅带外包装、
  供应商否认批次、复查改判六类情形的证据链均完整保留。

## 演示数据的六类情形

| 案件 | 情形 | 结果 |
|---|---|---|
| #1 / #2 | 同一防伪码两店重复（封签先好后破） | 正品 → 改判疑似假冒，全批冻结，两案归并 |
| #3 | 防伪标签涂层刮损、数字不全 | 暂挂待总部 |
| #4 | 型号/批次/码与销售记录不匹配 | 销售不匹配，冻结 |
| #5 | 顾客仅带外包装、无小票无实物 | 无法核对，不出结论 |
| #6 | 供应商书面否认批次 | 假冒，全批没收 |
| #7 | 气味存疑，实验室复检合格 | 证据不足 → 改判正品（两版结论） |

## 测试

```bash
python3 -m unittest discover -s tests -v     # 19 个用例
```

覆盖：调查归并、库存冻结（含并发竞态）、结论版本、门店权限、六类证据留存、
冻结批次筛选与对照页数据。

## 代码结构

```
app/db.py        SQLite 表结构与连接（WAL + 外键 + busy_timeout）
app/services.py  六大领域流程：事务、归并、比对、冻结、结论版本、权限、告知
app/adapters.py  模拟防伪查询平台 / 模拟短信通知
app/images.py    标准库直接编码 PNG 证据照片 + 文本凭证
app/seed.py      演示数据（含重复码与六类情形）
app/server.py    http.server 页面与 JSON API
run.py           一条命令入口
tests/           unittest 端到端测试
```
